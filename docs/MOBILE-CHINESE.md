# iPhone・iPadの中国語音声

2026-10-28時点で、iPhone・iPadの中国語音声の新規生成は提供しません。Safariで生成中にページが再読み込みされる報告に対し、現在のモデルを端末へ読み込ませ続けることを避けています。iOS系の識別はiPhone/iPad/iPodのUser-Agentと、iPadOSのMacIntel＋複数タッチポイントです。iOSのChromeに切り替えれば解消するという案内はしていません。

PCの中国語生成と英語生成の操作は維持します。iPhone向け画面ではPCで作成した音声の取り込みを案内します。PCでMP3を保存して端末へ送り、「PCで作成した音声を読み込む」から取り込む手順です。音声取り込み時には選択していた言語を保ち、取り込み後の言語変更でも音声クリップを失わないようにしました。取り込んだ音声の再生・A–B・速度変更・録音は既存の機能を使います。

## 検証した軽量化と採用しなかった理由

公式Kokoro v1.1-zh ONNXのrevision `6cc0f0d2ebe369a68b0df87c2b65c1af8c0ac3e3` を、Chromium・単一スレッドWASM・現在の読み変換で試しました。本文を外部AIへ送らず、モデルの取得はGETのみです。

| 候補 | 実測結果 | 判断 |
| --- | --- | --- |
| fp16 約164 MB | 短文では3声とも有限PCM。通常の長さの複数の文では3声とも全サンプルNaNとなった。短い文でも声によって失敗 | 不採用 |
| signed int8 約127 MB | ConvInteger(10)が未実装でセッション作成に失敗 | 不採用 |
| q4f16 約166 MB | 短文は有限PCMだが、長文では3声ともNaN | 不採用 |
| fp16の最適化basic/disabled/extended | 長文のNaNは解消せず | 不採用 |
| fp32のキャッシュ無効＋basic最適化＋prepacking無効 | 有限PCMは得られたが、Renderer最大常駐メモリーは減らなかった | 不採用 |

fp32の97トークンの例文では、RendererのVmHWMは1,405,116 KiB（約1.34 GiB）でした。上のfp32設定変更は1,412,444 KiBで、改善を確認できませんでした。fp16は892,860 KiBと小さくなりましたが、通常の文で不正な出力になるため公開版では使いません。これらはLinux Chromiumの1回の測定で、iPhoneの実測値や一般的な必要メモリー量ではありません。端末の実際の再読み込み原因をメモリー不足と断定するものでもありません。

短文の成功だけでスマートフォン対応済みとせず、入力を黙って切り捨てたり、不正な音声を成功として保存したりしません。iPhoneで失敗後に大型fp32モデルを自動で再試行するフォールバックも追加していません。異なる音声方式や外部AIへの自動切り替えはありません。

## ページ再読み込み時の案内

音声生成の開始前に、作業ID・言語・開始時刻・処理段階・試聴/全文の種別だけをsessionStorageへ記録します。原稿・教材名・ファイル名・録音・生成音声・エラー文は含めません。生成成功時には再生を試みる前に、失敗・中止・タイムアウト時にも所有するIDを確認して消去します。言語切り替え時はWorkerごと解放し、以前のWASMメモリーを使い回しません。

未完了の記録が残っているページを開き直すと、途中終了した可能性を表示します。記録は30分で期限切れとして扱い、表示後は消去します。手動の再読み込みやページ終了でも同じ記録が残り得るため、ブラウザーのクラッシュと断定しません。原稿の復元や生成の自動再開はしません。Safariがストレージも破棄した場合など、検出できない場合があります。
