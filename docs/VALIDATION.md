# 動作確認と未確認事項

## 実行環境と確認方法

2026-10-25、Linux・Node 24.19.0・npm 11.9.0・システムChromiumで確認しました。`npm ci`、`npm run build`、`npm test`、`npm run test:e2e` を使用します。

## 確認できたこと

- 型検査とViteの本番ビルド。
- 重要処理の自動テスト15件（中国語の変調・音素変換・未対応文字検出を4件追加）：英語の略語・小数・イニシャル、中国語の引用と句読点、混在文字の保持、長文末尾、実発話時間からの無音、文の時刻、サンプルの語尾、A–B境界、キャッシュ条件、WAVヘッダー。
- Chromiumのブラウザーテスト3件（以下の機能群）。
  - 実際のDOCXコンテナー、文字PDF、UTF-8テキストから本文抽出。テスト時に作った文書を使用。Wordソフトでのファイル作成はしていない。
  - 原稿編集、文分割・結合・任意改行での再分割、教材保存とリロード後の復元、言語切替。
  - 画像/空PDFで抽出不可の案内。実際に文字のないPDFを使用。
  - 持ち込みMP3の再生位置進行、A–Bの3回反復（0.1–0.5秒、間の無音0.1秒、再生速度1.5倍）。
  - Chromiumの仮想マイクで録音・停止・比較操作。比較時に再生中の要素が複数にならないこと。
  - A–Bと録音を保存し、リロード後に復元すること。
  - 実MP3エンコード、ダウンロード、ZIP展開。外部ツールffprobeでMP3のコーデックと長さを確認。2つの異なるテスト音（440Hz・880Hz）の分割出力をデコードし、周波数と長さで順序・内容の違い・語尾保持を検証。
  - モデル取得エラー、マイク拒否、IndexedDBのQuotaExceededErrorを注入し、案内と操作復帰を検証。この3つは実サービス障害・人の権限操作・実ディスク満杯を発生させたものではない。
  - 390pxと1280px幅で横スクロールが発生しないこと。
- 本番ビルドをローカルサーバーで起動し、MP3の取込み・エンコーダーWorker・保存を再検証。3秒の入力に対し、外部ffprobeで `codec_name: mp3`、`duration: 3.030187` を確認（エンコーダーの遅延とパディングを含む）。
- 本番ビルドの390px幅でも横方向のオーバーフローなし。PC/狭い画面のスクリーンショットを目視確認。

**テスト音は生成モデルの成果物ではありません。音声品質の検証には数えていません。** テスト用の資料・音声・録音は `/tmp` またはテストブラウザー内に作成し、リポジトリへ保存していません。

## 設定反映後に実音声で追加確認したこと

- 英語モデル92,361,116バイト、中国語q8モデル127,356,597バイトのダウンロードに成功。Hugging FaceのLFS SHA-256と一致。
- 英語5声・中国語3声で、公開モデルをNode CPUで実行して音声生成。
- Linux ChromiumのWorker / WebAssemblyで英語5声を実生成。中国語q8では出力が全NaNになることを検出し拒否。通常精度fp32（339,369,442バイト）に変更し、3声で有限の音声を実生成。
- 正規の環境プロキシCAをNSSへ登録し、TLS検証を有効に保ったブラウザーでネットワーク取得を確認。認証、APIキー、有料サービスは使用していない。
- 実際の画面操作で英語・中国語それぞれ共通原稿の試聴、声と速度確定、2文の全文生成、生成音声の再生位置進行、リピーティングの固定無音設定、MP3保存、生成音声を含む教材保存を確認。
- アプリが書き出した実生成音声のMP3を外部ffprobeで確認。英語2文+文間2秒で5.832秒、中国語2文+文間2秒で7.536秒。両方codec_nameはmp3。
- 英語原稿は `Take a deep breath. What matters to you today?`、中国語原稿は `请深呼吸。今天，对你来说什么最重要？`。
- 全候補の同一原稿の実生成音声は、Git対象外の `.validation-audio/` に試聴用MP3として用意。

上記はテスト音ではなくモデルが本文から生成した音声です。発音・声調・自然さ・広告のない発話全体について、人が聴いて確認したという意味ではありません。

## A–Bゲージと細かな再生速度の変更

- 単体テスト20件、ブラウザーテスト6件、本番ビルドが成功。
- マウスでA/Bをドラッグし、交差・音声範囲外への操作を有効な境界に制限することを確認。
- 短い音声での境界、キーボード、拡大・全体表示を確認。
- 31段階の選択肢、0.55/1.05/2.00倍の実際のHTMLAudioElement.playbackRate、preservesPitch、変更前後でA/B時刻が不変なことを確認。
- ゲージで設定した区間を1.05倍・3回・間の無音0.05秒で再生し、3回で停止・終了位置の一致を確認。
- 教材保存・リロード後にA/B・速度・リピート状態が復元されることを確認。
- モード変更でA/Bが解除される際は、リピート状態も解除して通常再生できるように修正。
- 390pxのタッチ対応ChromiumでCDPによる実タッチイベントのドラッグを検証。PC幅・390px幅のスクリーンショットを目視確認。

## 試聴・全文生成の進行表示と5秒移動

試聴と全文生成の処理状態を分離しました。試聴では押した声のボタンだけに回転マークと「試聴を準備中」を表示し、進捗・中止ボタンも試聴欄に出します。全文生成は専用ボタンの明示操作でのみ開始し、実行中だけ「全文生成中」と表示します。同時実行を防ぐため、試聴中は全文生成ボタンを無効にします。

再生ボタンの左右に5秒戻る・5秒進むを追加しました。停止中は停止を維持し、再生中は移動後も再生します。通常は0〜末尾、A–Bリピート中はA〜Bに収まります。区間の無音待機中に移動すると古い待機タイマーを取り消します。録音中は5秒移動を無効にします。前後の文への移動は下段に残しています。

- 単体テスト20件、ブラウザーテスト11件、本番ビルドが成功。
- 制御可能なテスト用Workerで、試聴中に全文生成が呼ばれないこと、各ボタンのaria-busy・回転マーク・進捗の区別、試聴キャッシュから全文への再利用、中止後の復帰を確認。このWorkerによる検証は実モデルの品質検証ではありません。
- 新規作成した12秒のテストWAVで、5秒移動、先頭・末尾、再生継続、A/Bの境界、区間内からの再開、無音タイマーの取消し、録音中の無効化を確認。
- 素早い移動やB到達に伴う古いplay()の中断を、現在の再生失敗として扱わないよう修正。
- 320px幅のChromiumで3つの主操作ボタンの幅・画面内配置を検証し、スクリーンショットを目視確認。スマートフォン実機の検証ではありません。

タイポのAI校正および録音へのAIフィードバックは、この変更には含めていません。現行の録音・聴き比べ機能は維持しています。

公開版`ba7ed86`でも、実際の英語モデルによる試聴を行い、その間は全文生成ボタンに処理中表示が出ず、文分割・全文生成も開始しないことを確認しました。明示的に全文生成を押すと2文の生成が完了しました。新規の合成テストWAVで公開版の5秒移動・停止状態維持・再生継続・320px幅の配置も確認し、ページのJavaScriptエラーはありませんでした。公開JS/CSSのSHA-256はローカルビルドと一致しています。検証はGET通信だけに制限し、実利用者の資料・録音は使用していません。
