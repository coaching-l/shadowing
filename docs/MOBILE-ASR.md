# 小型モデルでの英語MP3文字起こし

対象はiPhoneでの英語MP3文字起こしです。中国語生成を止める対策は解除し、英語ASRと持ち込み音声の操作を修正しました。

## 使い方

1. 言語を英語にし、「手元の音声で練習する」でMP3等を読み込みます。
2. 04の「音声を文字起こし」を開き、全体または選択したA–B区間を指定します。
3. 「音声を端末内AIで文字起こし」を押します。
4. 認識結果を聴き直して編集し、「この文字起こしを本文に反映」を押します。

元の音声・A–B設定は保ちます。文ごとの自動位置合わせは行いません。持ち込み音声は50 MB・20分、文字起こし区間は0.4秒〜20分です。録音フィードバックの0.4〜30秒・10 MB制限は別に維持します。中止・失敗では以前の文字起こし結果と音声を保ちます。無料・ログイン不要で、音声や本文は外部の推論APIへ送りません。初回のモデル取得通信はあります。

## モデルとメモリー

英語はWhisper tiny.en q8（`Xenova/whisper-tiny.en`、revision `79fb389fc764e7c395bd330e9531d9d32ada7049`）を使います。主な重みはencoder 10,124,913バイト＋merged decoder 30,727,382バイト、約41 MBです。従来も同程度の容量の多言語tinyを使っており、取得容量の大幅な削減ではありません。base.en q8は約77 MBと大きく、採用しません。中国語のASRは従来の多言語tinyです。

- 推論は単一スレッドWASM。WASM実行ファイルをアプリと同じ配信元から取得し、jsDelivrの既定パスへの依存を除きます。
- 英語専用モデルが受け付けないlanguage/taskの指定を渡しません。
- 長い音声は20秒前後（18〜22秒付近の静かな境界、末尾は最大24秒）の区間ごとに順番に処理します。全区間の特徴量をまとめて保持しません。境界は語の区切りを保証しないため、結果は確認が必要です。
- MP3のデコード前とASR開始前に以前のTTS Workerを終了します。用途・言語が変わる場合も追加AI Workerを使い回しません。
- 元音声の高サンプルレートPCMを複製せず16 kHzへ変換し、認識用PCMはWorkerへ転送します。練習用の単一取り込みクリップもコピーせず再利用します。
- 認識完了後はASR Workerをすぐ終了します。進捗が5分止まると終了し、利用者も中止できます。

短く分けてもWhisperのencoder内部は30秒分へ埋めるため、1回の推論負荷が長さに比例して小さくなるわけではありません。モデル容量と実行時メモリーは異なり、iPhoneでの全条件の安定性は未確認です。

## 検証

本番ビルドをLinux Chromiumで実行し、iPhoneのUser-Agent・390px幅・外部GET通信のみの条件で、実際のtiny.en q8と新規の合成MP3を使いました。短い英語と約40秒の英語を認識し、後者は2区間を順に処理して最後の「the final word is sunshine」まで認識しました。結果の編集・本文反映・元音声の再生・処理直後のWorker終了を確認しました。これはiPhone実機/Safariの検証ではなく、人の発音・雑音・重ね読みの精度や速度の保証でもありません。

単体テストではモデル指定・英語専用パラメーター・20分の区間連続性・逐次実行・無音/不正値の拒否・PCM転送・中止/タイムアウトを確認しています。ブラウザーテストは実MP3の取り込みを使い、ASR応答を制御してA–B保持・結果編集・明示反映・失敗/中止時の結果保持を検証しています。最新の件数は[VALIDATION.md](VALIDATION.md)を参照してください。
